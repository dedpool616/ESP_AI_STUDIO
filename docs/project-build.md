# Сборка открытого проекта

На Dashboard открыт блок «Сборка проекта» с кнопкой «Собрать проект», статусом
и журналом. Сначала сохраните изменения в Code Editor через «Сохранить всё».
Во время сборки редактор собираемого проекта доступен только для чтения.

Backend проверяет структуру проекта, плату sdkconfig и кэш CMake. Старый build
после переноса проекта не удаляется автоматически: показывается ошибка.
Сборка запускает Python выбранного в ESP-IDF Manager SDK и idf.py без shell.
Вторая сборка блокируется глобально. Переход между страницами не останавливает
процесс; при переключении проектов результат привязан к исходному пути.
Закрытие приложения разрешается после завершения сборки.

В окружении дочернего процесса используются проверенные пути Python, Git,
CMake, Ninja и компилятора, а также локальные инструменты SDK. Системные
переменные не изменяются. Component Manager отключён; проекты с манифестом
внешних компонентов в корне или main отклоняются. Проекты с собственными CMake
командами выполняют их при сборке, поэтому открывайте доверенные проекты.
Зависимости не устанавливаются, прошивка платы не выполняется.

Журнал хранится в памяти main process (последние 256 КБ) до следующей сборки
или выхода из приложения. Результаты ESP-IDF находятся в build открытого проекта.
Отдельный инструмент tools/esp-idf-smoke-build.cjs служит только для тестов;
он не запускается приложением. Его новые проекты создаются в C:\esp_projects.

Ручная проверка:

1. Открыть свой минимальный проект с выбранной ESP32-S3.
2. На Dashboard нажать «Собрать проект», проверить поступление вывода и итог.
3. Во время сборки перейти на Home и обратно; журнал и состояние сохраняются.
4. Изменить файл без сохранения: кнопка сборки недоступна, есть пояснение.
5. Сохранить всё и повторить сборку.
6. Внести синтаксическую ошибку в C, сохранить и собрать: статус «Ошибка»,
   диагностическое сообщение компилятора в журнале. Затем вернуть код.
7. Проверить отказ при sdkconfig для другой платы и при перенесённом кэше.
